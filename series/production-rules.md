# Production Rules

## Chapter Lifecycle

See the [production walkthrough](../production/getting-started.md) and
[stage prompts](../prompts/index.md) for practical inputs, outputs, and file locations.

1. Draft concept
2. Review outline
3. Write script
4. Define panel storyboard
5. Generate artwork
6. Check consistency
7. Revise
8. Approve
9. Archive final pages
10. Update continuity
11. Commit approved story files and push to the configured GitHub remote

## Page Production and Delivery

Write exact dialogue and plan balloons before final art. Produce an authorized
panel/page batch using actual character reference images, then assemble and
letter editable pages. Keep panel originals, page sources, lettering records,
and transcripts alongside composed page images.

Export draft review or final approved PDFs from composed pages in the correct
order. Visually inspect the exported PDF. A PDF is a delivery artifact, not
the sole editable source. Exporting does not approve canon or publish externally.

Before ending a chapter session, save a handoff with current stage, selected
versions, approval state, unresolved issues, and next action. New sessions
must read these records and supply reference images again.

## Working Sessions and GitHub

Maintain the project directory during each session. Update profiles,
relationships, continuity, and outstanding decisions as relevant.
Keep user-approved facts distinct from assistant proposals.

The user has authorized pushing each completed story to GitHub. A completed
story has passed QA and received creative approval. Inspect the diff, exclude
private sources and unrelated work, update the release index, commit the
approved story and related records, then push to the configured remote.
Report any push failure without claiming a successful release.
Planning updates alone are not completed stories.

## File Naming

Chapter directories: `chapter-001`
Artwork pages: `page-001.png`
Character directories: lowercase kebab-case

## Canon States

DRAFT: Experimental content
REVIEW: Pending approval
APPROVED: Accepted for publication
ARCHIVED: Retired but preserved

## Revision Rules

For recurring-character scene art, follow the
[reference workflow](../prompts/reference-workflow.md) and
[panel template](../prompts/scenes/manga-panel-template.md). Supply actual
reference images, record their versions and scene state, and review identity
and continuity before approving a panel. Do not repeatedly redesign characters
from their names or from the latest generated panel alone.

Never overwrite approved references without approval.
Record material changes in the change log.

## Story Rules

Characters should have coherent motives and realistic flaws.
Avoid simplistic heroes or villains.
Use subtle expressions and visual storytelling.
